# Camp Fire Migration Design

**Date:** 2026-03-02
**Baseline:** Tag `v0.1.0` (Garden codebase)
**Approach:** Delete and rebuild. Keep infrastructure, build Camp Fire systems fresh.

---

## 1. Data Model

### Resources (runtime state in SaveData)
- **Mana** (`float`): passively generated by flame, spent on crafting
- **Water** (`int`): discrete units stored in vases, spent on watering

### ScriptableObjects

**FlameConfig** (singleton config asset)
- `baseManaPerSecond: float`
- `manaPerLevel: float`
- `plotsPerLevel: int[]` — plot cap per flame level
- `upgradeCosts: float[]` — Mana cost per level

**SeedData** (one per seed type)
- `seedName`, `growthDurationHours`, `waterRequired`
- `preferredWeather: TriggerCondition` — weather match = quality bonus
- `baseYield: int`, `icon: Sprite`, `growthSprites: Sprite[]`

**VaseConfig** (vase tier config)
- `capacity: int`, `craftCost: float`, `upgradeCosts: float[]`
- `fillDurationMinutes: float`

**GardenPlantData** (permanent trees/shrubs)
- `plantName`, `growthDurationHours`, `yieldItem`, `yieldAmount`
- `yieldIntervalHours: float`, `waterRequired: int`

**RecipeData** (Apotheke mixing)
- `recipeName`, `ingredients: List<IngredientEntry>`, `result`, `resultQuantity`

### SaveData
```csharp
[Serializable]
public class SaveData
{
    public int version = 1;
    public float mana;
    public int flameLevel = 1;
    public List<VaseSave> vases;
    public List<PlotSave> plots;
    public List<GardenSave> gardens;
    public List<string> seedInventory;
    public List<InventoryItem> items;
    public float lastManaCollectTime;
}
```

## 2. Systems & Managers

### FlameManager
Heart of the camp. Owns flame level, drives Mana generation.
- Accumulates Mana per second: `flameLevel * manaPerLevel + baseManaPerSecond`
- `GetMaxPlots()`: plot cap from config
- `UpgradeFlame()`: spends Mana, increments level
- Offline Mana accumulation on load via `lastManaCollectTime` delta

### PlotManager
Harvest-once planting cycle.
- `CraftPlot()`: spends Mana, adds empty plot (gated by flame level)
- `Plant(plotIndex, seedName)`: consumes seed + water
- `Water(plotIndex)`: deducts water, marks watered (growth starts after watering)
- Growth: `GameTime.UtcNow - plantTime` vs `growthDurationHours`. Weather match = 25% speed boost.
- `Harvest(plotIndex)`: quality multiplier (0.8–2.0) influenced by weather. No letter tiers, no Sync Shield.

### GardenManager
Permanent plants. Built fresh (not refactored from Greenhouse).
- `Plant(gardenIndex, plantName)`: consumes seed + water
- Mature gardens yield fruit on `yieldIntervalHours` interval
- No re-watering after initial planting (v1 simplification)

### VaseManager
Water storage.
- Starts with 2 vases
- `SendToCollect(vaseIndex)`: Mallum collects water, stamps fillStartTime
- `UseWater(amount)`: deducts across vases
- `CraftVase()` / `UpgradeVase(index)`: spends Mana

### ApothekeManager
Seed storage, analysis, mixing.
- `AnalyzeSeed(seedName)`: reveals preferred weather
- `Mix(recipe)`: consumes ingredients, produces result

### LetterManager
Social send/receive. Stubbed for v1 (data model ready, no backend).

### VisitorSystem
Daily night events. Visitor gifts seed/water, tells a story. Once per day.

### Kept from Garden
- **WeatherService** — unchanged core (GPS, API, enrichment)
- **SaveManager** — same pattern, new SaveData shape
- **CurrencyManager** — simplified to Mana + Water
- **GameManager** — stripped, handles init and new-player setup
- **NotificationService** — reuse for visitor/harvest notifications
- **Utils** — GameTime, MoonPhaseCalculator, CalendarEvents, TimeUtils

## 3. UI Architecture

### Layout
Single persistent top-down campsite view. Bottom bar opens slide-up overlay panels.

```
┌──────────────────────────┐
│  Weather Bar (top)       │
├──────────────────────────┤
│                          │
│     CAMPSITE VIEW        │
│     (true top-down)      │
│                          │
│   Flame, Plots, Vases,   │
│   Gardens — tappable     │
│                          │
├──────────────────────────┤
│ [Apotheke] [Letters] [Craft] │
└──────────────────────────┘
```

### UI Controllers
- **CampFireUI** — root orchestrator (replaces HortusUI)
- **CampsiteViewUI** — camp object layout, tap handling
- **WeatherBarUI** — weather display + expandable forecast
- **BottomNavUI** — 3-button navigation
- **ApothekeUI**, **LettersUI**, **CraftUI** — overlay panels
- **FlameUI**, **PlotUI**, **VaseUI**, **GardenUI** — object interaction panels

### File Structure
```
Assets/UI/Documents/CampFireRoot.uxml

Assets/Resources/UI/Templates/{PlotItem,VaseItem,GardenItem,SeedCard,RecipeCard,LetterCard,CraftItem}.uxml
```

## 4. Migration Phases

### Phase 1: Clean Up
Delete all Garden-specific code, assets, UI, and tests.
Keep: WeatherService, SaveManager, CurrencyManager, NotificationService, Utils, UI Toolkit infra, asmdef, project settings, ThirdParty icons.
Delete: GeneticsEngine, HarvestEngine (variant system dropped).

### Phase 2: Data Layer
New SaveData, FlameConfig, SeedData (simplified), VaseConfig, GardenPlantData, RecipeData.
Adapt CurrencyManager to Mana + Water. Adapt SaveManager.
Create initial ScriptableObject assets.

### Phase 3: Core Managers
FlameManager, PlotManager, VaseManager, GameManager.
Wire to SaveManager. Verify Mana generation and basic plant/water loop.

### Phase 4: UI
CampFireRoot.uxml, stylesheets, CampFireUI orchestrator, all sub-controllers, templates.

### Phase 5: Extended Systems
GardenManager, ApothekeManager, VisitorSystem, LetterManager (stubbed).

### Phase 6: Tests
New EditMode test suite for all Camp Fire logic.

### Phase 7: Scene
Rebuild scene with Camp Fire hierarchy: camera, lighting, managers, UI Document.

---

## 5. Decisions Log
- **UI**: Single campsite view + slide-up overlay panels (not swipeable pages)
- **Variants**: Dropped. Weather affects quality/speed only, no visual variants.
- **Gardens**: Built fresh (not refactored from Greenhouse)
- **Currencies**: Mana + Water only (no third currency)
- **Scope**: Full GDD (all systems) in first milestone
- **Perspective**: True top-down (not isometric)
- **Code approach**: Delete and rebuild, keep infrastructure only
